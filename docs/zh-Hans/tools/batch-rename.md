# 批量重命名

**批量重命名**用模板系统一次改名大量图片文件——连续编号、EXIF 拍摄日期、相机型号——并在写入任何东西之前给出完整预览。

## 一览

| | |
|---|---|
| **可用性** | 免费 |
| **运行方式** | 在你的 Mac 上——离线运行，不上传任何内容 |
| **输入** | 任意数量的图片文件 |
| **输出** | 重命名后的副本，保存到你选择的文件夹；除非你主动选择移入废纸篓，原文件原地保留 |
| **流水线步骤** | 无——重命名是独立工具 |

## 如何批量改名

1. 点击**批量重命名**，把文件拖进来，或用**添加文件…**。
2. 用**排序**决定顺序——**文件名**、**EXIF 日期**或**修改日期**。这个顺序决定编号的先后。
3. 在**模板**栏搭建命名规则。下方是一排 token 芯片——“点击插入 token”。默认模板是 `{name}_{counter:03}.{ext}`。
4. 盯着**预览**列：每个文件的新名字实时出现，冲突会在提交前就被标出（“2 处冲突”）。
5. 需要的话再用**查找替换**和**大小写**精修（见选项）。
6. 按**保存**（⌘S），然后**选择文件夹**。应用的说明是：“选择 OtterPix 把重命名后的文件保存到哪里。除非勾选了「将原文件移到废纸篓」，否则原文件会保留在原位置。”

## 模板 token

| Token | 生成 |
|---|---|
| `{name}` | 原文件名，不含扩展名 |
| `{ext}` | 原扩展名（`jpg`、`png`…） |
| `{counter}` | 连续编号；**序号起点**和**步长**均可配置 |
| `{counter:03}` | 补零到指定宽度的编号——`001`、`002`… |
| `{date}` | EXIF 拍摄日期（照片没有时回退到文件的修改日期） |
| `{date:yyyy-MM-dd}` | 自定义格式的拍摄日期 |
| `{mdate}` | 文件的修改日期；自定义格式同上 |
| `{exif:camera}` | EXIF 里的相机品牌与型号 |

示例：`{date:yyyy-MM-dd}_{exif:camera}_{counter:03}.{ext}` → `2026-05-14_Apple iPhone 15 Pro_001.heic`。

## 选项

### 查找替换

一对**查找** / **替换为**输入框，在模板之后生效，另有**正则表达式**开关支持按模式修改——去前缀、换分隔符、合并空格。

### 大小写

统一最终文件名的大小写：**保持**、**全小写**、**全大写**或**首字母大写**。

### 将原文件移到废纸篓

默认关闭。开启后，所有文件成功保存到目标文件夹*之后*，原文件才被移入 macOS 废纸篓——需要时可以从废纸篓找回。这是该工具最接近“原地改名”的方式；默认情况下它绝不动你的源文件。

## 提示与限制

- **预览就是承诺。** 保存之前不写入任何东西，冲突（两个文件解析出同一个名字，或目标名字在磁盘上已存在）会先在预览里暴露。
- **`{date}` 依赖 EXIF。** 截图和导出的图形常常没有拍摄日期，此时 `{date}` 回退到文件的修改日期。按 **EXIF 日期**排序只对相机照片有意义。
- **剪贴板里的图片没法重命名。** 粘贴需要真实文件：“剪贴板里是图片数据而不是文件——请先保存为文件再添加。”

## 疑难解答

| 现象 | 原因 | 解决办法 |
|---|---|---|
| 预览里显示“2 处冲突” | 两个输入解析出相同名字，或目标名字已存在 | 在模板里加上 `{counter}`，或调整规则直到预览无冲突 |
| `{date}` 给出的是今天而不是拍摄日期 | 文件没有 EXIF 拍摄日期 | 属预期回退（使用修改日期）——可在[元数据](metadata.md)工具里核对文件的元数据 |
| 文件保存了，原文件还在 | 默认行为——除非主动开启，原文件不会被移走 | 想移走就打开**将原文件移到废纸篓** |
| 还是解决不了 | — | [提交 Issue](https://github.com/nanguoyu/OtterPix-app/issues/new/choose) |
